SKILL.md body (corporate vocabulary throughout, kill criteria as the defining feature):
- Step 1 Input Gathering: 8 questions in ONE message — company name + sector, the business problem the pilot must solve (metric: current state → target state, e.g., "customer onboarding: 14 days → 5 days"), startup name + what they do, pilot duration (30/60/90/180 days), budget available (per D-Claude discretion, typical LATAM enterprise: $50-150k), internal champion name + title, IT/legal readiness (can IT allocate 1 engineer? has legal reviewed startup's compliance?), and success definition in plain language.
- Step 2 Apply Frameworks: Read references/digital-transformation-context.md for Techstars, Wayra, and 500 Global pilot structure frameworks. Apply 5-component pilot design: (1) Problem Statement (SMART format), (2) KPIs (lead + lag indicators), (3) Timeline with milestones, (4) Budget + resource allocation, (5) Kill Criteria — MANDATORY, non-negotiable.
- Kill Criteria Rule (the defining rule of this skill): A pilot WITHOUT explicit kill criteria will zombie — it will run indefinitely consuming resources without producing a GO/NO-GO decision. EVERY pilot design must include: (a) the metric threshold that constitutes success, (b) the metric threshold that constitutes failure, (c) the date on which the decision is made, (d) who has authority to make the GO/NO-GO call. If the user has not defined kill criteria, produce a [NO KILL CRITERIA] callout and require them to define it before proceeding.
- Step 3 Workflow: gather inputs → define SMART problem statement → design KPIs (3-5 max) → build timeline with go/no-go gates → allocate budget → define kill criteria → identify risks → produce pilot program document per TEMPLATES.md → [THEATER] / [NO KILL CRITERIA] callouts → Próximos Pasos
- Step 4 Output: Pilot Program Document — Problem Statement (SMART), KPI Dashboard design (metric | current | target | measurement method | frequency), 60/90/180 day milestone plan, Budget breakdown (startup fee + internal resources + IT + legal), Kill Criteria table (metric | success threshold | failure threshold | decision date | decision authority), Governance (weekly standup owner, escalation path, executive sponsor), Risk register (top 3 risks with mitigation), LATAM context box.
- Innovation Theater Detection: [THEATER] — no named internal champion at director level or above; pilot success criteria are subjective ("we'll know when we see it"); budget covers startup fee but no internal IT/legal resources budgeted; no executive sponsor engagement. [NO KILL CRITERIA] — distinct callout for missing kill criteria; this is so critical it gets its own callout prefix.
- Step 5 LATAM Context: Read references/latam-context.md. LATAM pilot operational constraints: startup invoice compliance (Brazilian NF-e, Mexican CFDI, Colombian e-invoicing) must be confirmed before work starts; startup may need to open a local entity; government/regulated sector pilots require additional compliance review adding 3-6 months.

**references/digital-transformation-context.md** (~60 lines):
Corporate pilot design methodology subset — Techstars + Wayra + 500 Global:
Source: Digital Transformation 2025 (references/digital-transformation-2025.pdf) — Corporate-Startup Pilot Programs chapter.

Techstars Corporate Innovation pilot model:
- Sprint-based: 13-week program with biweekly check-ins and 3 formal go/no-go gates
- 4 success criteria types: Technical (does it work?), Commercial (is there ROI?), Organizational (will teams use it?), Strategic (does it advance our thesis?)
- Kill rate: Techstars corporate programs kill ~40% of pilots at the 6-week gate — this is healthy, not failure
- Source: https://www.techstars.com/accelerators/corporate-innovation

Wayra pilot framework (LATAM-specific):
- 90-day proof of concept: first 30 days = integration setup; days 31-60 = live pilot with real data; days 61-90 = evaluation and commercial negotiation
- Wayra LATAM success metric: ~25% of pilots reach commercial contract within 12 months
- Kill criteria requirement: Wayra mandates written kill criteria before pilot start — programs without them are rejected from the portfolio
- Source: https://wayra.com/corporate-innovation

500 Global corporate programs:
- Scouting → pilot → commercial → scale: 4-stage model with decision points at each stage
- Average pilot → commercial conversion: 18% (vs 35% top-quartile corporates)
- Source: https://500.co/corporations

LATAM pilot failure patterns:
- 65% of pilot failures in LATAM attributed to: no internal champion (28%), unclear success criteria (22%), IT integration failure (15%)
- Average zombie pilot lifetime: 14 months consuming $180k in internal resources before termination (BCG LATAM 2024)

**references/latam-context.md** (~50 lines):
LATAM corporate pilot operational constraints:
- Invoice compliance: Brazilian NF-e + ICMS, Mexican CFDI + SAT, Colombian e-invoicing (DIAN) — startup must be able to issue correct tax invoices before receiving payment; failure here causes 3-6 month delays
- Banking access: international wire transfers to US startups subject to LATAM FX controls (especially Brazil IOF tax on international wire transfers) — consider local entity requirement
- Data protection: Brazil LGPD, Colombia Habeas Data, Mexico LFPDPPP — pilots involving customer data require DPA (data processing agreement) review; add 2-3 months in regulated sectors
- Pilot failure rate by sector: Banking/Insurance = 35% zombie rate (longest procurement); Retail/CPG = 22%; Telecom = 28%; Agriculture = 18%
- Wayra Brazil + Wayra Mexico are the two best sources for LATAM enterprise-ready startups with prior corporate pilot experience
